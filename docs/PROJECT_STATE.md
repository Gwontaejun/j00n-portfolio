# 프로젝트 상태 및 인수인계

최종 갱신: 2026-08-27

이 문서는 채팅 기록 없이도 다른 컴퓨터나 새 AI 세션에서 작업을 이어가기 위한 현재 상태 요약이다. 구현과 내용이 달라지면 즉시 갱신한다.

## 현재 콘셉트

`J00N Portfolio`는 사용자가 개발자의 실제 작업 책상을 둘러보며 웹 프로젝트, 앱 프로젝트, 프로필을 확인하는 3D 포트폴리오다. 방에는 책상, 모니터, 휴대폰과 거치대, 키보드, 마우스, 장패드, 코르크보드, 조명, 비 오는 창문이 있다.

인트로는 `J00N` 타이핑 후 `Portfolio`가 페이드인되고, 인트로가 완전히 사라진 다음 3D 장면을 보여준다.

인트로가 끝날 때마다 4단계 온보딩 가이드를 표시한다. 모니터 → 휴대폰 → 프로필 → 방명록 순서이며 이전·다음 버튼으로 이동하고 마지막 `확인` 버튼 또는 ESC 키로 닫는다. 확인 여부는 브라우저 저장소에 기록하지 않으므로 페이지에 다시 진입하거나 새로고침하면 항상 표시된다. 책상 기본 화면 우측 상단의 도움말 아이콘을 누르면 언제든 1단계부터 가이드를 다시 열 수 있다.

방명록 단계의 안내 문구는 포스트잇 목록과 겹치지 않도록 코르크보드 오른쪽 빈 영역에 배치하고, 연결선만 방명록 포스트잇 영역으로 이어진다.

가이드의 오브젝트 강조는 CSS 도형 마스크를 사용하지 않는다. `GuideSceneRenderer.tsx`가 일반 Three.js 장면을 렌더한 뒤 전체 딤 패스를 적용하고, 현재 단계의 실제 GLB 그룹을 별도 렌더 레이어에서 다시 그린다. 모니터와 휴대폰·거치대는 실제 모델 실루엣대로 강조한다. 프로필과 방명록 단계에서는 코르크보드 전체가 아닌 해당 Drei `Html` 영역만 각각 딤 처리에서 제외한다.

### 프로필

- 왼쪽 측면 벽의 `cork-board.glb` 전면에 로컬 이력서 첫 페이지 이미지를 인쇄물처럼 부착한다.
- 코르크보드의 프로필 용지는 Drei `Html`의 `distanceFactor = 0.6`을 사용해 초기 크기보다 2배 크게 표시한다.
- 프로필 용지는 코르크보드 오른쪽 영역의 로컬 좌표 `[0.028, 1, -0.72]`에 배치한다. 투명 클릭 버튼은 같은 중심의 `[0.025, 1, -0.72]`를 사용하며, 프로필 가이드 도트도 기본 카메라에서 계산한 화면 좌표에 맞춘다.
- 프로필 미리보기는 Drei HTML 이미지 대신 `profile-page-1.png`를 고해상도 Three.js 텍스처로 불러와 실제 평면 mesh에 적용한다. sRGB, mipmap, 선형 필터와 최대 anisotropy를 적용해 카메라 정지 후 CSS 3D 래스터화로 흐려지는 문제를 피한다. 실제 mesh는 깊이 검사를 받으므로 코르크보드 앞면 좌표 `x = 0.235`에 배치하고, 어두운 방 조명에서도 문서가 사라지지 않도록 톤다운된 `meshBasicMaterial`을 사용한다. 투명 HTML 버튼은 클릭·키보드 포커스·호버 눈 아이콘만 담당한다.
- 코르크보드의 빈 공간에는 서로 다른 종이색과 미세한 회전을 적용한 HTML 포스트잇을 한 줄에 3개씩 배치한다. 첫 칸은 `방명록 등록하기`이고 이후 칸에 방문자 메모가 표시된다. 한 화면에는 4행, 총 12칸까지 보이며 이를 초과하면 코르크보드의 포스트잇 영역 내부에만 세로 스크롤이 생긴다.
- 책상 화면에서 `방명록 등록하기` 포스트잇을 처음 누르면 작성 폼을 열지 않고 카메라만 코르크보드 정면으로 부드럽게 이동한다. 이동 후 같은 포스트잇을 다시 누르면 작성 폼이 열린다. 방명록 포커스 상태에서는 다른 책상 오브젝트의 입력을 막고 ESC 또는 좌측 상단 뒤로가기 버튼으로 기본 시점에 복귀한다.
- 등록 포스트잇뿐 아니라 기존 방명록 포스트잇을 선택해도 작성 폼은 열지 않고 카메라가 코르크보드 정면으로 이동한다. 각 방명록은 키보드로도 선택 가능한 버튼이다.
- 모니터·코르크보드 카메라 전환은 종료 임계점에서 목표 좌표를 강제로 복사하지 않는다. 보간된 위치에서 자연스럽게 정지시켜 마지막 프레임이 목표점으로 툭 붙는 현상을 방지한다.
- 방명록 목록은 클라이언트에서 Supabase를 직접 호출하지 않고 Next.js Route Handler `GET /api/guestbook`을 거쳐 Supabase `guestbook_entries`에서 최신순으로 조회한다. 닉네임 없이 메시지와 포스트잇 색상만 표시하며 로딩, 빈 목록, 환경변수 누락 및 조회 실패 상태는 코르크보드 안의 대체 포스트잇으로 처리한다.
- 방명록 등록은 `POST /api/guestbook` Route Handler가 담당한다. 작성 폼은 닉네임 없이 150자 메시지와 포스트잇 색상만 받고, 서버에서 길이·허용 색상·허니팟을 다시 검증한다. 원본 IP 대신 서버에서 만든 방문자 해시를 저장해 동일 방문자의 등록을 30초 간격으로 제한한다. INSERT에는 브라우저에 노출하지 않는 `SUPABASE_SECRET_KEY` 또는 레거시 `SUPABASE_SERVICE_ROLE_KEY`가 필요하다.
- 방명록 작성 폼은 Drei `Html transform`의 축소 렌더링에서 분리해 `document.body`의 일반 2D DOM 포털로 표시한다. 브라우저 원본 해상도로 선명하게 렌더링하며, 방명록 포커스 카메라는 코르크보드에 가까운 정면 시점을 유지한다.
- 코르크보드의 방명록 포스트잇 목록은 코르크보드 면을 따르는 Drei `Html transform`과 내부 스크롤을 유지한다. 현재 안정값은 `distanceFactor = 0.5`, 내부 `zoom = 1.7`이다. 배율 변경만으로 정지 상태의 흐림을 해결하려던 실험은 효과가 확인되지 않아 모두 복구했다.
- 코르크보드 자체에는 프로필 클릭·호버 이벤트를 넣지 않는다. 프로필 용지에만 딤, 눈 아이콘, 포인터 커서, 상세 열기 동작을 적용해 추후 방명록 포스트잇과 독립적으로 상호작용할 수 있게 한다.
- 방명록을 보기 위해 카메라가 코르크보드 정면으로 이동한 상태에서도 프로필 용지는 클릭할 수 있으며, 선택하면 프로필 상세 화면을 연다.
- 이력서 원본은 `public/pdf/profile.pdf`, 미리보기는 `public/pdf/profile-page-1.png`를 사용한다.
- PDF 공개 경로는 `src/features/desk-interaction/model/resume.ts`에서 관리한다.
- 클릭하면 별도의 프로필 상세 뷰가 부드럽게 열리고 닫힌다.

## 공간 배치

- 방 크기는 책상 폭의 약 2배인 폭 `12.7`, 깊이 `8.6`으로 구성한다.
- 책상은 원본 크기를 사용하며 `WORKSPACE_OFFSET = [-3.05, 0, -1.95]`로 왼쪽·뒤쪽 벽에 밀착한다. 모니터, 휴대폰·거치대, 키보드, 마우스, 장패드는 `DESKTOP_ITEMS_OFFSET_X = -0.55`를 적용해 책상 위에서 왼쪽으로 모은다.
- 책상, 모니터, 휴대폰·거치대, 키보드, 마우스, 장패드는 하나의 작업공간 그룹으로 함께 이동한다. 프로필 코르크보드는 왼쪽 측면 벽에 고정한다.
- 비 오는 창문은 방 중앙보다 살짝 왼쪽인 `x = -0.45`에 두며 약 `2.85 × 1.9` 크기의 작은 창으로 구성한다. 프레임, 유리, 비 셰이더와 창문광도 함께 이동하며 커튼은 사용하지 않는다.
- 왼쪽 측면 벽은 작업공간과 코르크보드·포스트잇 방명록 공간으로 사용한다.
- 기본 카메라는 왼쪽 작업공간과 코르크보드를 함께 보여주는 비대칭 구도를 사용한다.
- `public/3d-models/cork-board.glb`는 왼쪽 측면 벽 안쪽의 `[-6.2, 1.2, -1.45]`에 밀착해 배치한다. 모델 원본의 넓은 면이 YZ 축이라 별도 회전 없이 측면 벽과 평행하게 두고 앞면이 방 안쪽을 향하게 한다.
- 방 안의 모델과 벽 재질이 분명하게 보이도록 ambient light `0.34`, directional 달빛 `0.9`, 창문 rect-area light `0.38`을 사용한다. 책상 맨 왼쪽 뒤 `[-2.48, DESK_TOP_Y + 0.02, -0.78]`의 반투명 원통형 무드등은 앰버·오렌지 계열이며, intensity `1.25`, distance `5.8`의 따뜻한 point light가 왼쪽 벽과 코르크보드 주변으로 퍼진다.

## 상호작용 상태

### 책상

- 기본 카메라 위치: `[-3.47, 2.66, 2.46]`
- 기본 카메라 타깃: `[-4.21, 1.67, -2.59]`
- 기본적으로 카메라 이동은 잠겨 있다.
- 장면 준비 전에는 우측 상단 카메라 버튼을 표시하지 않는다.
- 모니터, 휴대폰, 프로필 상세가 활성화되면 다른 대상의 입력을 차단한다.

### 모니터

- 비활성 상태에서 화면 호버 시 회색 딤과 큰 눈 아이콘을 표시한다.
- 클릭하면 카메라가 모니터 앞으로 천천히 이동한다.
- 모니터 내부는 Windows 계열 데스크톱 문법을 사용한다.
- 모니터 화면 앞에는 화면보다 약간 넓은 옅은 하늘색 rect-area light를 두어 키보드, 장패드와 책상 전면에 화면광이 은은하게 투영되도록 한다. 오른쪽 아래에는 낮은 세기의 보조 point light를 두어 검은 장패드에 묻히는 마우스 윤곽만 살짝 보완한다.
- 작업표시줄에서 프로젝트를 선택·검색하며 화면에는 선택한 프로젝트 하나만 표시한다.
- 모니터 확대 전에는 내부 버튼이 동작하지 않는다.
- 프로젝트 창은 Windows식 최소화·닫기 버튼과 부드러운 전환을 사용한다.

### 휴대폰

- 비활성 상태에서 호버 시 모니터와 같은 눈 아이콘 계열을 표시한다.
- 클릭하면 휴대폰이 현재 위치에서 사용자 앞으로 이동하고 정면을 향한다. 카메라는 움직이지 않는다.
- Android 스타일 상태 표시와 하단 탐색을 사용한다.
- 하단 탐색 순서: 최근 앱(왼쪽), 홈(가운데), 뒤로가기(오른쪽).
- Duck Routine 상세 순서: 헤더/상태, Play Store·GitHub, 기술 스택, 앱 소개, 주요 기능.
- 상세 내용은 휴대폰 화면 안에서 스크롤할 수 있다.

## 렌더링 및 리소스 상태

- Canvas는 DPR 1, 비활성화된 안티앨리어싱, demand 렌더 루프를 사용한다. 상시 렌더 루프 전환은 방명록 선명도에 효과가 없어 복구했다.
- 창문의 비 셰이더가 활성화된 동안에는 애니메이션을 위해 매 프레임 렌더링한다.
- 키보드는 `low-poly-keyboard.glb`를 사용하고 그림자를 생성하지 않는다.
- 장패드는 별도 GLB 대신 `DeskAccessories.tsx`의 라운드 도형으로 생성한다.
- 모니터·휴대폰·프로필 화면은 Drei `Html`을 사용하며 정면에서만 보이도록 처리한다.
- 휴대폰 이동 프레임은 HTML 좌표 계산보다 먼저 실행하고 월드 행렬을 즉시 갱신한다.
